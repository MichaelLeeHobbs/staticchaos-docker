# Bug & content specs

Triaged **bug** and **area/content** reports live here, one file per GitHub issue.

- **Filename:** `<issue#>-<YYYY-MM-DD>-<slug>.md` (e.g. `57-2026-06-27-trial-master-login-block.md`).
- **Template:** copy [`../issue-spec-template.md`](../issue-spec-template.md).
- **Lifecycle:** written by the issue-ops workflow once the report is understood, then the
  maintainer reviews. On "build it" the fix is implemented, tested on dev, PR'd, merged,
  deployed, and the issue is closed with a summary.

Feature and balance specs go in [`../features/`](../features/). Privacy: use GitHub handles and
issue numbers only — never Discord aliases (this repo is public).
